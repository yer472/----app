# 学习笔记（XXBJ）

按「科目 → 章节 → 笔记」三级结构记录课堂笔记的本地应用。纯前端、无后端，数据全部存在本机浏览器的 IndexedDB 里。

完整的产品设计见 [XXBJ.md](XXBJ.md)。

## 快速开始

```bash
npm install
npm run dev      # 开发服务器，浏览器打开提示的地址
npm run build    # 类型检查 + 打包到 dist/（同时生成 dist/sw.js）
npm run serve    # 起本地服务器，http://127.0.0.1:24816/
npm run lint     # oxlint
npm run icons    # 从 public/icon.svg 重新生成图标（改了图标才需要跑）
npm run verify:pwa   # 端到端验证离线能力（需要先 build）
npm run verify:board # 端到端验证绘图功能（自己起 dev 服务器，不用先 build）
npm run verify:blockdiagram # 端到端验证模块图（同上）
npm run verify:shortcuts # 端到端验证键盘快捷键（同上）
npm run verify:symbols   # 端到端验证机构符号与机构语义（同上）
npm run verify:m45       # 端到端验证深色模式、最近编辑、错误页、拖拽排序（同上）
```

**浏览器要求：Chrome 或 Edge。** Firefox / Safari 对 File System Access API 支持不全，自动备份功能会不可用。

## 日常使用

**地址是 `http://127.0.0.1:24816/`，这个地址不要改。** 它同时决定了四件事：笔记存在哪、离线缓存存在哪、装出来的桌面应用是哪一个、任务栏上那个图标是谁。换一个端口不会迁移任何东西——你会看到一个空的应用、任务栏上多出来的第二个图标，而笔记还留在旧端口下。

第一次装：

```bash
npm run build
npm run serve
```

然后在 Edge 里打开 `http://127.0.0.1:24816/`，点地址栏右侧的「安装」图标（一个带加号的显示器）。装完会有自己的任务栏图标，`Alt+Tab` 能切过去。

**装完之后就不需要开着服务器了。** Service Worker 把整个应用（约 3.5MB，148 个文件）缓存了下来，双击图标直接打开，服务器关着也行。实测过：关掉浏览器、服务器全程没启动、重新打开，应用正常。

只有两种情况需要再跑一次 `npm run serve`：

- **改了代码要更新。** 重新 `npm run build`，起一次服务器，在设置页点「立即更新」。
- **离线缓存被清掉了**（比如手动清理了浏览器数据）。应用会打不开，跑一次服务器打开一次就恢复了，笔记数据不受影响。

## 编辑器

基于 **Milkdown Crepe**——存储的是纯 Markdown，编辑时即时渲染（敲 `## ` 当场变成标题，符号自动隐藏）。输入 `/` 会弹出插入菜单。

**图片**：直接 `Ctrl+V` 粘贴截图、或者把图片文件拖进编辑区。图片会自动压缩到长边 1600px 以内再存进 IndexedDB，正文里留一个 `asset://<附件id>` 引用。

格式策略是**跟着输入走**：截图（PNG）仍然存 PNG，照片（JPEG）仍然存 JPEG。不一律转 JPEG 是因为文字截图用 JPEG 会出现振铃状的糊边，而且 PNG 对这类内容往往体积更小、还能保住透明区域。

**自动保存**：停止输入 1 秒后落盘，标题和正文用同一套机制。离开页面、切换笔记时都会兜底保存一次，不会丢内容。

## 首页、置顶与排序

首页最上面是**最近编辑**——最多 6 篇，按最后修改时间倒序，点一行直接回到那篇笔记。这一栏回答的是「我刚才在写什么」，所以：

- **按更新时间排，不是创建时间。** 翻出一篇三个月前的旧笔记改两个字，它就上来了，这是对的。
- **置顶的笔记不会因此插队。** 置顶是标记，不是编辑——点一下置顶按钮**不会**改「最近编辑」的顺序，也不会改章节列表里那行「更新于」。这一条曾经是错的（置顶顺手写了时间戳），自检脚本里有一条专门钉着它。
- 一篇笔记都没有时，这一栏整个不显示。

**按科目和章节排序**：把鼠标移到卡片上，右上角（章节列表则在左边）会出现一个 `⠿` 手柄，拖它就能改顺序。也可以**把手柄用 Tab 键选中，再按 `Alt+↑` / `Alt+↓`**——两条路都能用，因为拖拽本身没法被自动化测试驱动，只留一条路的话这个功能就只能靠人工发现它坏了。

排序**不进撤销栈**（没有全局撤销，画板和编辑器各自有）。拖动时在列表外松手就当作取消，顺序还原。

侧栏的「科目」列表跟着首页的顺序走，两处是同一份 `order`。侧栏里没有第二个拖拽入口——一次点击的成本，换掉三份要维护的命中几何。

## 深色模式

跟着系统、或者手动切成浅色/深色，入口在侧栏底部那个按钮（点一下循环切换）。

**启动时不会先白一下。** 主题真正的数据源是 IndexedDB 里的设置，要异步读；所以 `index.html` 里有一段内联脚本，读 `localStorage` 里那个**提示位**先把 `<html>` 的 class 摆正。提示位只是提示——过期了、缺失了都行，设置读完会被纠正回正确值。自检脚本里有一组用例专门验这个真值表（包括「提示位和数据库不一致时以数据库为准」）。

**正文里的图片在深色下会压暗一档，并带一道细边框。** 理由：画板导出的图是**写死的白底黑线**（SVG 放进 `<img>` 里是独立文档，继承不到页面的 CSS），而贴进来的课件截图大多也是白底——深色下它们都是一块刺眼的白。压暗用的是 `filter: brightness(0.9)`：**局部对比度基本不动**（图里的黑线照样清楚），压掉的是整块白的绝对亮度。

- 只影响显示。**导出的 SVG、备份文件夹里的文件、打印出来的东西仍然是纯净的白底黑线。**
- 不做反色：白底黑线的图纸反色是对的，但彩色课件截图反色会变成负片。
- 不区分「图形」和「照片」：区分要么得给 blob 地址挂片段（会破坏「改完图正文立刻更新」那条链路），要么加一遍 DOM 后处理反查附件类型。一个纯装饰的差别不值得引入两个静默失效点。

**一处改不了的**：`manifest.webmanifest` 里的 `theme_color` / `background_color` 是静态的，深色下**启动那一瞬间**的底色仍是白的（装成桌面应用后能看见一下）。manifest 是构建产物里的静态文件，运行期改不了。

## 绘图

笔记页右上角的「插入图形」按钮打开画板。工具有**选择、直线、矩形、椭圆、手绘、橡皮**（快捷键 `V`/`L`/`R`/`O`/`P`/`E`），网格吸附（`▦` 按钮切换），撤销重做（`Ctrl+Z` / `Ctrl+Shift+Z`，深度 50 步），选择工具下可拖动、`Delete` 删除。完整的按键清单见「键盘快捷键」一节。

画完点「完成」，图会插到正文的**光标位置**。再次点「插入图形」可以列出本篇笔记已有的图，点「编辑」接着改。

**画的时候有三件事会自动帮你对齐：**

- **端点吸附**：你的落点靠近任何已有端点（直线的两端、矩形的四角、符号的锚点）时会精确吸上去，画面上出现一个绿圈提示。吸上去是**严格同一个坐标**，不差一丝——这是「拖动铰链联动构件」能成立的前提。
- **按住 Shift 约束角度**：直线和构件锁到 15° 的整数倍，矩形变正方形、椭圆变正圆。此时网格吸附让位（不然角度会被网格毁掉）。
- **页脚实时读数**：正在画的长度和角度。

落点的优先级是**端点吸附 > 角度约束 > 网格吸附**。三者冲突时按物理意义排序：「把杆接在铰链上」比「这一笔正好 15°」要紧。

### 机构符号库

画板左侧是一栏符号面板，分两段：**标准符号**（内置的 10 个）和**我的符号**（自己画的）。两者用法一样——点一下符号，再到图上点一下（带杆的则按住拖一段）就放上去了。

内置的 10 个按运动副/构件/传动/从动件/原动件分五组：转动副、固定铰链、移动副、构件、机架、齿轮副、带传动、凸轮、电动机、原动件。

放下去之后，选中它会出现蓝色手柄：拖**端点手柄**改位置，拖上面那个**圆形手柄**改方向（按住 Shift 按 15° 吸）。

> ⚠️ **关于标准**：这些符号是按 **GB/T 4460—2013《机械制图 机构运动简图用图形符号》**（代替 1984 版）的**图形特征**手绘的，**不是标准原图的复制件**；齿轮副的节圆一律等径（应用里没有齿数/传动比参数），也没有实现线型规范（点划线、粗细线比例）。用途是课堂笔记里的示意图，**不作为制图依据**。
>
> 照标准来的三处：构件的杆用**两倍粗实线**；转动副的小圆圆心就是回转轴线（所以它就是那个锚点）；机架类符号画上短斜线、移动副的导路方向靠旋转对齐。

### 机构语义：拖动铰链会带着构件走

画一个四杆机构试试：放两个固定铰链，再用「构件」把铰链两两连起来（端点会自动吸住）。然后：

- **拖动活动铰链**（选中一根构件，拖它端点上的蓝色手柄）→ 连在这个铰链上的构件一起动。
- **拖动固定铰链** → **不动**，并在页脚说明原因。「固定铰链」不动才是它名字的意思。
- **想挪整台机构** → 拖机架本体，整套一起平移。

这不是约束求解——没有任何求解器，也不重算位置。它就是一条规则：**重合的端点永远一起走**。吸附保证了「铰链」在数据上真的是同一个坐标，这条规则保证它不会被拖散。

### 自定义符号

点面板里「我的符号 → ＋新建」会进符号编辑模式：一块小画布，用和画板一样的工具画，画完起个名字保存。蓝色十字是**插入点**——以后放到图上时，这个点就落在你点下去的位置，也是它和别的构件连在一起的地方。

- 自定义符号**只支持「点符号」**：定尺寸、可旋转、点一下放置。不能在画板上拉长它（要不同尺寸就存两个）。
- 符号里**不能放符号**（编辑模式的工具栏里没有符号面板，构造上就不可能）。
- **改了或删了一个自定义符号，已经画好的图不会跟着变。** 每张图在插入时就把定义**抄了一份存在自己里面**，那份副本是权威的。想更新老图，把里面那个符号删掉重新放一个。
  这么设计是为了两件事：删符号**绝不会**破坏任何已画好的图；画板里看到的和存进正文那张 `<img>` 永远是同一个几何。
- 自定义符号**跟着备份走**（它和笔记一样是你创作的内容，不是配置）。注意恢复是覆盖式的，所以恢复一份旧备份会清空现有符号库——设置页的确认框里会显示「符号库 N 个会被替换」。

### 存的是一张自带数据的 SVG

可见的图元负责显示，场景数据（每个图元的类型和坐标）内嵌在 SVG 的 `<metadata>` 里负责「下次还能接着改」。这样一个文件既是渲染结果又是源数据，正文里只需要一行普通的 Markdown 图片引用，于是备份、孤儿清理、导入导出、离线缓存全部沿用既有管线，一行都不用改。

场景格式有个版本号，**按内容写**：只用普通图形的图写 1，用了符号的写 2。这样万一回滚到旧版本，随手画的那些图还打得开，只有真的用了符号的才打不开——而那本来就该打不开。

编辑已有的图时是**覆盖同一个附件**，正文里的引用保持稳定；覆盖之后会主动刷新页面上那张 `<img>`，否则你会看到「数据库里明明是新的、屏幕上还是旧的」。

**两个要知道的取舍：**

- **图形颜色不跟随主题。** 正文里的图是 `<img src="blob:...">`，SVG 在 `img` 里是独立文档，**继承不到页面的 CSS**。所以按制图惯例固定成白底黑线——浅色主题下完全正确，深色主题下是一张「白图纸」，由显示层统一压暗一档（见「深色模式」一节），导出的文件不受影响。
- **图形不进搜索。** 场景数据在附件里，而且搜索会先把正文转成纯文本（图片整段丢掉），所以搜「四杆机构」搜不到那张图。

**这个功能不做的事：** 不做运动学仿真，不做参数化求解（改一个杆长不会让整个机构重算位置）。也不做手绘笔迹的分段擦除（橡皮是整笔擦除）、不做符号嵌套、不做符号缩放、不支持导入 SVG 当符号。详见 [XXBJ.md](XXBJ.md) 的 §1.4。

### 验证

- `npm run verify:board` —— 22 项断言，覆盖画、撤销重做、保存、备份往返、孤儿清理。其中一条是**画布渲染与导出渲染逐属性对拍**：同一份场景，两边渲染出来的元素必须逐字段相同。它守的是「几何只在 `render.tsx` 里算一次」这个重构——在那之前画布和导出是两份各自算几何的实现，漏改一处是静默的。
- `npm run verify:symbols` —— 17 项断言，覆盖符号目录自检、机构语义（拖铰链联动、机架钉死、拒绝拖动）、放置、内联定义、备份往返。
- `npm run verify:blockdiagram` —— 见「模块图」一节。

这些脚本都会自己起一个 dev 服务器（端口 5199~5202），跑完自动清理自检数据。

## 模块图

画板里除了「自由图形」，还有一个「模块图」模式，用来画教材上那种系统框图：一排彩色方框，方框之间连着箭头，底下一根通栏长条。

**模块和流向是两种图形**，在左上角切换模式后，工具栏换成 `模块`（`N`）和 `流向`（`F`）。模式只决定工具栏显示哪几个按钮——一张图上可以既有模块又有自由线条，场景格式不分家。

**流向不存坐标，只存「从哪个模块到哪个模块」。** 箭头的位置是**算出来**的，所以拖动模块时箭头自动跟着走，不需要手工对齐。走的是正交折线（横平竖直），从源模块的边缘出发、指到目标模块的**中心正面**——底下那根通栏长条往上的箭头，落在每个方框的中心正下方，而不是长条自己的中心。

**改文字**：双击模块，或者点一下**已经选中**的模块，会出现一个就地输入框（Enter 确认、Esc 取消）。中文输入法在选词时按 Enter 是选词、不会误提交。文字变长时模块**只往宽处长、不缩回去**——手动拉宽的通栏长条不会被一次改字打回原形。

**摆位置**：拖动方框类图形时会给对齐辅助线（和别的方框的左/中/右、上/中/下对齐时出现虚线，并把位置吸过去）。选中模块后四角有方块手柄可以改尺寸。

**配色**：选中模块点色块改填充色，选中流向点色块改线条色（同一个色板，流向那一份把白色换成了墨色——白线画在白纸上等于没有）。标签的黑白是按底色亮度算出来的，深色底自动换白字。

**删模块会连它的流向一起删。** 这不是顺手做的，是为了保证「不存在指向已删除模块的流向」这条不变量——那种流向画不出来、点不中、也删不掉。删除的唯一入口（`removeShapes`）负责级联，橡皮的标红集合也把连带删掉的流向算进去，所以「屏幕上标红的」和「松手真删的」是同一个集合。万一还是出现了（只可能来自手工改过的文件），打开这张图时会**把那几条丢掉并提示**，而不是整张图拒开——拒开的代价是连保存一起禁用，只能去改导出的 SVG，那是 M6.5 记过的那类故障。

**这个功能不做的事**：不做自动排版（位置全靠手摆，这正是它能画出通栏长条的原因——Mermaid 就是死在自动排版上）、不做连线避让、不做正交线的拐点手动调整、不做多行文字。模块和流向**不能放进自定义符号**：符号的定义会被摊平成一份零件表，摊平之后没有「场景」，流向的几何算不出来。

**验证**：`npm run verify:blockdiagram`，24 项断言，端口 5202。最要紧的几条是：通栏长条→方框的箭头必须落在方框中心正下方（第一版就是这条红的，它抓住了「入口取源的中心」这个写错的规则）、删模块的级联与撤销、以及**跨渲染器对拍**——那条断言原来只比几何属性，对填充色和文字是瞎的，这次先把属性清单扩到 `fill` / `font-family` / `text-anchor` / 文字内容，再动渲染（并且临时把导出侧的填充去掉，确认它真的会红）。

## 搜索

侧栏的搜索框（或 `Ctrl+K`）跳到搜索页，跨全部科目检索标题和正文。结果里命中处会高亮，并显示所属科目 / 章节，可以按科目收窄范围。

匹配前会先把正文转成**纯文本**，不是直接匹配 Markdown 原文——否则搜 `asset` 会命中每一张图、搜 `##` 会命中每一个标题，结果里全是噪声。

实现是内存里的全表扫描（`SearchRepository`）。几百篇笔记是几毫秒级；到设计文档说的「1000 篇 / 1 秒」那个量级，需要给正文加一份归一化的小写文本字段并建索引。现在不提前做，是因为真正的瓶颈要等有真实数据才知道在哪。

## 键盘快捷键

**完整的清单在设置页里**（「设置与备份」→ 键盘快捷键），按 `Ctrl+/` 可以直接跳过去并高亮那一节。清单分四组，每组都标了生效范围——因为这四组的实现者根本不是同一个：

| 分组 | 说明 |
| --- | --- |
| 全局 | 任何页面都生效 |
| 页面 | 跟着当前所在页面变 |
| 编辑器 | **由编辑器（Milkdown Crepe）自带，不是本 App 实现的**。光标在正文里时它们优先于全局快捷键 |
| 绘图 | 只在画板打开时生效 |

除了清单里有的，`Ctrl+F` 是**故意不接管**的——留给浏览器原生的页内查找（在一篇长笔记里找一句话时有用），全局找东西走 `Ctrl+K`。

### 两条支撑整个设计的机制

**1. 全局层靠 `event.defaultPrevented` 给编辑器让位。** 所以 `Ctrl+B` 在正文编辑器里是**加粗**、在别处才是折叠侧栏——同一个键在不同焦点下做不同的事，而且不需要维护「焦点在不在编辑器里」这种判断。ProseMirror 命中按键时会 `preventDefault()`（`node_modules/prosemirror-view/dist/index.js`），它的监听器在 `window` 的上游，所以能看见。代码块里的 CodeMirror、输入法的组合状态也走同一条路。

**2. 对话框或画板开着时，全局快捷键整体让位。** 靠的是一个模块级的浮层计数（`lib/shortcuts/overlay.ts`），不是查 DOM——画板没有 `role="dialog"`，按属性查恰好会漏掉最需要挡的那个（里面有未保存的图）。少了这一条，在「新建科目」里填了一半再按 `Ctrl+K` 会被导航走，连输入框一起卸载。

**组合键只写在 `lib/shortcuts/catalog.ts` 里一处**，绑定代码只引用条目 id。所以清单里写的和按下去生效的在数据上就是同一份，不可能对不上——自检脚本还会双向比对「目录里写了没绑」和「绑了目录里没写」。

`Ctrl+N` / `Ctrl+T` / `Ctrl+W` 这类**浏览器保留键**一律不用：页面根本收不到，绑了等于没绑。自检脚本里有一条专门守着这个。

验证方式是 `npm run verify:shortcuts`，30 项断言、端口 5198。它跑的几条都是「看起来能跑但其实是坏的」：对话框开着时快捷键还在生效、`Ctrl+B` 被侧栏抢走导致没法加粗、笔记→笔记切换把上一篇的正文写进下一篇、画板里 `Shift+R` 也切工具、浮层计数只加不减导致所有全局键永久失效、目录和绑定对不上。

排序用的 `Alt+↑` / `Alt+↓` 在「首页、置顶与排序」一节里说明。

## 数据安全与备份

**这是本项目最重要的一组功能。** 笔记存在浏览器的 IndexedDB 里，站点数据被清理就会全部丢失。设计文档 §7.4 定了三层防护，入口在侧栏「设置与备份」：

| 层级 | 实现 |
| --- | --- |
| 第 1 层 | 启动时请求持久化存储权限（`navigator.storage.persist()`）。浏览器可能不批，设置页会如实显示状态 |
| 第 2 层 | 自动备份到用户选的文件夹：镜像（`data.json` + `笔记/科目/章节/标题.md` + `images/`）+ 每日快照 zip（保留 7 天） |
| 第 3 层 | 设置页的「导出为 zip 文件」 |

导出格式是**开放**的：`笔记/` 里的 `.md` 用记事本、VS Code、Obsidian 都能直接打开，图片是 `images/` 下的普通文件，不依赖本 App。详细说明见 [XXBJ.md](XXBJ.md) 的 §7.4 和 M3 实施记录。

### 数据库自检

开发服务器跑起来后访问 `/dev/db-check`，可以一键验证 IndexedDB 的读写与级联删除是否正常。它会创建临时数据并在结束时清理干净，不会污染真实笔记。等功能稳定后这个页面可以删掉。

## 出错的时候会发生什么

有三层，覆盖的是**互不相交**的失败位置：

| 层 | 管什么 | 长什么样 |
| --- | --- | --- |
| 内容区错误边界 | 某个页面自己的查询/渲染崩了 | 侧栏和导航**都还在**，可以直接去别的页面；带「重试」——原地重试（重新挂载 + 重新订阅） |
| 路由错误页 | 布局、侧栏这一层崩了 | 整页，只有「重新加载」和「回到科目列表」 |
| 启动时数据库打不开 | 隐私模式、存储被禁用、库损坏 | 整页红块，说明原因并给出排查步骤 |

没有这些之前，任何一种错误都会掉进 react-router 自带的错误界面：**英文标题 + 完整堆栈**，而这是个全中文的笔记本应用。

**给出什么建议是按故障类型分的**，这件事有硬要求：存储配额满的时候，可以说「先导出一份备份、再删几篇带大图的笔记」，**绝不能说「清理一下浏览器数据」**——照做的话几年的笔记就一起没了。分类和措辞都在 `src/lib/errors.ts` 里，集中一处。

**写操作失败不再静默。** 删除、置顶、新建笔记这些点一下就走的动作，原来有几处是裸 `await`（失败变成未处理的 promise，界面上什么反应都没有）或者只有 `finally`（失败静默）。现在：

- 删除确认失败时**对话框不关**，把原因显示在里面——关掉的话用户会以为删成功了。
- 新建笔记、置顶失败时页面顶部出现一条红字提示。
- 删除前那次「将删除 N 个章节」的统计失败也不影响删除本身，只是如实说「统计失败」。

**「加载中」和「还没有」是两种状态。** 数据没读完时显示的是加载态，读完确实是空才显示引导式空状态——画板的「我的符号」原本把两者混成了一个，会先闪一句「还没有。点新建画一个」，看起来像你的符号不见了。

验证方式是 `npm run verify:m45`，30 项断言、端口 5201。它故意把东西弄坏来验错误路径（打桩让查询抛错、让删除失败、让新建失败），每组用例**先断言桩真的被调用了**——不然「页面没报错」可能只是桩没生效，那就是一条永远绿的假断言。

## 离线与安装

**为什么能脱开服务器**：`scripts/build-sw.mjs` 在每次构建后扫一遍 `dist/`，把所有资源写进 `dist/sw.js` 的预缓存清单，清单内容的哈希当缓存名。Service Worker 装好之后，导航请求由它直接用缓存的 `/index.html` 应答，客户端路由交给 React Router 解析。

几个不显然的设计决定：

- **预缓存跳过 `.woff` 和 `.ttf`。** 每个 KaTeX 的 `@font-face` 都把 `woff2` 列在 `src` 的第一位，而 Edge 支持 woff2，后面两个格式永远不会被请求。这一条省掉 40 个文件约 798KB。
- **`install` 里不调 `skipWaiting()`，`activate` 里不调 `clients.claim()`。** 如果调了：你开着应用的时候重新构建，新 SW 会立刻接管并删掉旧缓存，而运行中的页面内存里还是旧模块图，它懒加载 `NotePage` 时请求的是新哈希文件——那些文件已经不在磁盘上，路由会静默挂掉。延迟之后，旧页面继续用旧缓存服务，你点「更新」才切换。
- **代价是：因为导航走缓存优先，普通刷新永远拿不到新版本。「立即更新」是唯一的更新入口。** 所以这个提示必须显眼：有新版本时，**应用底部会出现一条横幅**，点上面的「立即更新」即可（设置页的「应用与离线」里也有同样一个按钮）。光是重新打开应用就会自动检测到新版本，不需要手动去点「检查更新」。

  > 这条横幅是吃过亏才加的。加完绘图功能之后，应用里装着的是旧版本、界面上找不到新按钮，而唯一能发现新版本的入口藏在设置页深处——不会有人没事去翻设置页。既然「更新」是唯一的路，提示就不能只待在一个角落。
- **`fetch` 里先判断协议再判断 origin。** `blob:` URL 的 origin 就是页面自己的 origin，只判 origin 会把笔记里的图片请求也拦下来，而 CacheStorage 只接受 http(s)，缓存操作会直接抛。
- **资源请求失败时绝不回退到 `index.html`。** 模块脚本收到 HTML 会报 `Unexpected token '<'`，把「文件缺失」伪装成语法错误。

验证方式是 `npm run verify:pwa`，22 项断言，包括「清空 HTTP 缓存后断网仍能打开」和「关掉浏览器重开、服务器全程没启动仍能打开」。

### 为什么自己写服务器而不用 `vite preview`

两个原因。一是端口必须固定且**绝不自动切换**——`serve.mjs` 遇到端口被占用会直接报错退出，因为静默换端口会让你的笔记「消失」（它们还在旧端口下）。二是 `vite preview` 对任何 404 都回 `index.html`，于是一个缺失的分片会返回 HTML，浏览器报 `Unexpected token '<'`，把「文件没了」伪装成语法错误。`serve.mjs` 的 SPA 回退只对不带扩展名的路径生效。

## 注意事项

- **备份权限按会话过期。** 重新打开 App 后需要点一下「重新授权」——这是浏览器的安全模型，绕不过去。
- **备份文件夹里的 `笔记/` 和 `images/` 只增不删。** 在 App 里删掉一篇笔记，文件夹里对应的 `.md` 不会被清理。这样做是为了绝不误删用户文件；恢复以 `data.json` 为准，残留文件不影响结果。
- **IndexedDB 按浏览器 + 用户配置隔离。** 换浏览器或换用户配置打开，看到的是空的。装成桌面应用之后请固定用它作为入口。
- **应用图标在安装时就被 Chromium 快照下来了。** 之后改 `public/icon.svg` 不会更新任务栏图标，需要卸载重装（卸载不会删数据）。
- **装完之后设置页的「浏览器占用」会涨约 3.5MB**，那是离线缓存。不是泄漏。
- **自动备份只在 App 开着的时候跑。**
- **侧栏折叠之后怎么展开：按 `Ctrl+B`，或者点左边那条窄栏上的 `»`。** 折叠时侧栏是**整个卸载**的，没有别的入口——这条窄栏按钮是专门为此加的。
- **`Alt+N` 需要人工确认一次。** 自动化测试测不到输入法：中文输入法正在选字时浏览器把按键报成 `'Process'`，快捷键会静默不生效。10 秒自检：微软拼音切到中文 → 敲 `nihao` 让候选窗弹出来 → 按 `Alt+N`（**没反应是正常的**，输入法在选字）→ 按 `Esc` 关掉候选窗 → 再按 `Alt+N`，**这一下必须有反应**。如果仍然没反应，说明这个组合在中文环境下不可用，换成 `Ctrl+Alt+N` 并同步改 `catalog.ts` 和 `XXBJ.md`。
- **画板里的机构符号需要人工看一眼。** 符号的图形是按 GB/T 4460 的**图形特征**手绘的（见「绘图 → 机构符号库」），不是标准原图。自动化测试只能验「放上去的位置、个数、联动关系对不对」，验不了「画出来像不像」。找出课本上一张四杆机构的图，照着画一遍，顺便看拖动是否符合直觉——30 秒。
- **`Ctrl+S` 需要人工确认一次**：按下去应该**不弹** Edge 自己的「保存网页」对话框（靠 `preventDefault` 压掉）。注意编辑器把正文交给保存层有最多 200ms 的延迟（见 `XXBJ.md` 的 M4 实施记录），所以刚敲完立刻按可能漏掉最后一两个字，随后那次自动保存会补齐，不会丢数据。
- **排序用的 `Alt+↑` / `Alt+↓` 需要人工确认一次。** 自检脚本里有一条「App 的绑定不许占用浏览器保留键」的断言，但 CDP 注入的按键**绕过浏览器进程**，所以「这个组合在真人手里收得到吗」自动化测不出来（`Alt+N` 那条也是同样的情况）。10 秒自检：在首页把鼠标移到某个科目卡片上，`Tab` 到那个 `⠿` 手柄上，按 `Alt+↓`——**那一项应该往下走一格，而且焦点还在它上面**（可以连按）。如果没反应，说明这个组合被浏览器或输入法占了，换成 `Ctrl+Alt+↑/↓` 并同步改 `catalog.ts` 和 `XXBJ.md`。
- **模块图里改文字要人工确认一次输入法。** 自检能验「双击出输入框、打字进场景、Enter 提交、Esc 取消、一键撤销」，但**测不到输入法**：CDP 注入的按键绕过输入法，而中文输入法在选词时 `isComposing` 为真（`key` 甚至会是 `'Process'`），确认候选词的那个 Enter 不该被当成「改完了」。10 秒自检：在模块上双击进入编辑 → 切微软拼音 → 敲 `nihao` 让候选窗弹出来 → 按 Enter **应当是选词、输入框还开着** → 关掉候选窗再按 Enter，这一下才提交。
- **对齐辅助线的手感要人工拖一次。** 自检验的是「同一个指针位置，从不同方向拖过来落点相同」（没有迟滞），验不了好不好用。真鼠标拖一个方框靠近另一个，看它是否吸住、辅助线画在哪几条线上。吸不住或者太黏（想微调却被拽走）就调 `src/components/board/scene.ts` 的 `ALIGN_THRESHOLD`（默认 6 个图纸单位）。
- **深色下要人工扫一眼有没有漏网的白块。** 自检脚本会算对比度（「深灰画在深灰上」那种它是抓得住的，真抓到过一次），但「这一块看着刺眼」是审美判断，脚本算不出来。切到深色把首页、章节页、笔记页、画板各翻一遍，重点看图片和画板里的图纸——它们**故意**是白的（只压暗了一档），要确认压暗的程度合不合适：太亮刺眼、太暗看不清图里的线。这个值在 `src/index.css` 的 `.dark .note-editor .milkdown img` 里，改一个数字就行。
