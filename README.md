# 学习笔记（XXBJ）

按「科目 → 章节 → 笔记」三级结构记录课堂笔记的本地应用。纯前端、无后端，数据全部存在本机浏览器的 IndexedDB 里。

完整的产品设计见 [XXBJ.md](XXBJ.md)。

## 快速开始

```bash
npm install
npm run dev      # 开发服务器，浏览器打开提示的地址
npm run build    # 类型检查 + 打包到 dist/
npm run lint     # oxlint
```

**浏览器要求：Chrome 或 Edge。** Firefox / Safari 对 File System Access API 支持不全，自动备份功能会不可用。

## 在 Windows 上当桌面应用用

开发阶段用 `npm run dev` 在浏览器里调试就够了。日常使用时，在 Edge 里打开地址后点地址栏的「安装」图标，它会变成独立窗口应用——有自己的任务栏图标、能用 `Alt+Tab` 切换，离线也能用。

## 目录结构

```
src/
├── types/models.ts     领域模型，对应文档 §4
├── db/index.ts         Dexie 实例 + schema + 存储权限
├── repository/         数据访问层，页面组件只调这里，不直接用 Dexie
├── lib/                纯函数工具（时间、Markdown 处理、格式化等）
├── store/              Zustand 全局状态（主题等）
├── components/
│   ├── layout/         整体布局与侧边栏
│   └── ui/             基础组件
└── pages/              各页面
```

**为什么要多一层 `repository/`：** 所有数据库操作都收敛在这个目录里，页面组件不直接使用 Dexie。这样将来若要加云同步或换存储方案，只改这一层，页面代码不动。

## 编辑器

基于 **Milkdown Crepe**——存储的是纯 Markdown，编辑时即时渲染（敲 `## ` 当场变成标题，符号自动隐藏）。输入 `/` 会弹出插入菜单。

**图片**：直接 `Ctrl+V` 粘贴截图、或者把图片文件拖进编辑区。图片会自动压缩到长边 1600px 以内再存进 IndexedDB，正文里留一个 `asset://<附件id>` 引用。

格式策略是**跟着输入走**：截图（PNG）仍然存 PNG，照片（JPEG）仍然存 JPEG。不一律转 JPEG 是因为文字截图用 JPEG 会出现振铃状的糊边，而且 PNG 对这类内容往往体积更小、还能保住透明区域。

**自动保存**：停止输入 1 秒后落盘，标题和正文用同一套机制。离开页面、切换笔记时都会兜底保存一次，不会丢内容。

### 数据库自检

开发服务器跑起来后访问 `/dev/db-check`，可以一键验证 IndexedDB 的读写与级联删除是否正常。它会创建临时数据并在结束时清理干净，不会污染真实笔记。等功能稳定后这个页面可以删掉。

## 注意事项

**数据安全是这个方案最大的风险点。** 笔记存在浏览器的 IndexedDB 里，站点数据被清理就会全部丢失。设计文档 §7.4 定了三层防护，其中**自动备份到本地文件夹（M3）必须与编辑功能同期上线**，不能拖到最后做。

在 M3 完成之前，请不要用它记录唯一一份的重要笔记。
